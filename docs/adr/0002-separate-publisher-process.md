# ADR 0002. Отдельный процесс `publisher` для публикации outbox

- Статус: Accepted
- Дата: 2026-07-10

## Контекст

Outbox-поллер (ADR 0001) можно запускать как фоновую задачу в lifespan API либо
как отдельный процесс. API масштабируется по числу HTTP-реплик, а поллеру нужен
контролируемый параллелизм и независимый жизненный цикл.

## Решение

Публикация вынесена в отдельный entrypoint `app/publisher/main.py`. Поведение
зависит от профиля:

- **local** (`OUTBOX_PUBLISHER_ENABLED=true`) — поллер поднимается в lifespan
  API для удобства локальной разработки (один процесс).
- **production** — в lifespan API выключен; `publisher` работает отдельным
  контейнером/процессом.

## Альтернативы

- **Только в lifespan API** — при N репликах API получаем N конкурирующих
  поллеров (защита есть через `SKIP LOCKED`, но масштабирование поллинга
  привязано к числу HTTP-реплик).
- **Cron/лямбда по расписанию** — сложнее обеспечить низкую задержку и graceful
  shutdown.

## Последствия

- Публикация масштабируется и деплоится независимо от API.
- Больше процессов в docker-compose (`publisher`, `webhook-dispatcher`,
  `consumer`) — выше эксплуатационная сложность, но чёткое разделение
  ответственности.
